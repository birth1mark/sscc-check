What is an SSCC?

The Serial Shipping Container Code (SSCC) is an 18 digit GS1 identifier used in logistics to uniquely identify a physical shipping unit, a pallet, box, roll cage, or any other logistic unit. It is the primary identifier used in supply chain transactions between trading partners.

SSCCs appear in two main contexts:

  • Physically, encoded in a GS1 128 barcode (a variant of Code 128) printed on pallet labels
  • Electronically, transmitted in EDI messages such as DESADV (Despatch Advice / ASN) and IFTMIN (Forwarding Instruction) in segments like GIN+BJ

The SSCC is always accompanied by the Application Identifier (AI) 00, which signals to any GS1 compliant system that what follows is an SSCC.

SSCC Structure

An SSCC has exactly 18 digits, structured as follows:

AI Extension GS1 Company Prefix Serial Reference Check Digit
(00) 3 56012345 00000001 6
not stored 1 digit 7 to 10 digits variable 1 digit
  • AI (00), Application Identifier. Always (00) for SSCCs. Not part of the 18 digits, it is a label that precedes them.
  • Extension digit, A single digit (0 to 9) assigned by the company to extend the numbering capacity.
  • GS1 Company Prefix, Issued by the local GS1 member organisation to the company. Length varies from 7 to 10 digits depending on the prefix allocation. The first 3 digits identify the issuing GS1 member country.
  • Serial reference, Assigned sequentially or randomly by the company to uniquely identify each logistic unit. Length varies inversely with the GCP length.
  • Check digit, Calculated from the preceding 17 digits using the GS1 modulo 10 algorithm. Used to detect transcription errors.
Important: The GS1 Company Prefix identifies the organisation that issued the SSCC, not necessarily the country of origin of the goods. A Portuguese company with prefix 560 may ship goods manufactured anywhere in the world.

Check Digit Algorithm

The SSCC check digit uses the standard GS1 Modulo 10 algorithm. Given the 17-digit body:

  1. Starting from the rightmost digit, multiply alternating digits by 3 and 1
  2. Sum all products
  3. Check digit = (10 . (sum mod 10)) mod 10

Worked Example

Body: 35601234500000001

Position (from right) 123456789 1011121314151617
Digit 100000005 43210653
Multiplier 313131313 13131313
Product 3000000015 492301859
Sum = 68 . Check digit = (10 . (68 mod 10)) mod 10 = (10 . 8) mod 10 = 2

Full SSCC: (00) 35601234500000001 2

Quick check: If the result of (sum + check_digit) mod 10 === 0, the SSCC is valid. This is the fastest way to validate an existing 18 digit SSCC.

Common Mistakes

1. Confusing the AI with the SSCC digits

The AI (00) is a label, not part of the 18 digits. When a barcode is scanned with a GS1 128 reader, the raw output is often 00 followed by the 18 digits, giving 20 characters total. Always strip the leading 00 before validating the check digit.

2. Wrong digit count

An SSCC body is always exactly 17 digits (before the check digit) or 18 digits (including it). Numbers with 19, 20 or more digits are either GTINs, IBANs, or other identifiers, not SSCCs.

3. Padding zeros

Some ERP systems store SSCCs in fixed width fields padded with leading zeros. A 20 character field starting with 00 followed by an 18 digit SSCC, or a 21 character field where the last character is a line number, always extract exactly 18 digits for the SSCC.

4. GS1 prefix vs country of origin

The GS1 prefix (first 3 digits of the SSCC after the extension digit) identifies the GS1 member organisation that issued the company prefix, not the country where the goods were made or shipped from. A company registered in Portugal (560) may ship from a warehouse in Spain.

JavaScript Implementation

Here is a complete, independent JavaScript implementation for validating and generating SSCC check digits. It uses BigInt to safely handle the large numbers involved.

/**
 * Calculate the GS1 check digit for a 17 digit SSCC body.
 * @param {string} body17 . 17 digit string (no check digit)
 * @returns {number} check digit (0 to 9)
 */
function getCheckDigit(body17) {
    let sum = 0;
    const digits = body17.split('').reverse();
    for (let i = 0; i < digits.length; i++) {
        sum += parseInt(digits[i]) * (i % 2 === 0 ? 3 : 1);
    }
    return (10 - (sum % 10)) % 10;
}

/**
 * Validate an 18 digit SSCC string.
 * @param {string} sscc18 . 18 digit SSCC (without AI prefix)
 * @returns {{ valid: boolean, expected: number, provided: number }}
 */
function validateSSCC(sscc18) {
    const digits = sscc18.replace(/\D/g, '');
    if (digits.length !== 18) throw new Error('SSCC must be 18 digits');

    const body     = digits.substring(0, 17);
    const provided = parseInt(digits[17]);
    const expected = getCheckDigit(body);

    return { valid: provided === expected, expected, provided };
}

/**
 * Normalise any SSCC input to an 18 digit string.
 * Handles: 17 digits (generates CD), 18 digits, 20 digits with AI "00".
 */
function normaliseSSCC(raw) {
    const d = raw.replace(/\D/g, '');
    if (d.length === 17) return d + getCheckDigit(d);
    if (d.length === 18) return d;
    if (d.length === 20 && d.startsWith('00')) return d.substring(2);
    throw new Error(`Unexpected length: ${d.length}`);
}

// Examples
validateSSCC('356012345000000012');  // { valid: true, expected: 2, provided: 2 }
validateSSCC('356012345000000019');  // { valid: false, expected: 2, provided: 9 }
normaliseSSCC('00356012345000000012'); // '356012345000000012' (strips AI)
normaliseSSCC('35601234500000001');   // '356012345000000012' (generates CD)

Python Implementation: Check Digit & Batch Validation

For data pipelines, ERP extractors, and backend services, here is the clean Python 3 implementation of the GS1 Modulo 10 check digit calculation and SSCC validator:

def calculate_sscc_check_digit(body17: str) -> int:
    """
    Calculates the GS1 Modulo 10 check digit for a 17-digit SSCC payload.
    """
    if len(body17) != 17 or not body17.isdigit():
        raise ValueError("SSCC payload must be exactly 17 digits")
    
    # Alternate multipliers 3 and 1 starting from the rightmost digit
    digits = [int(d) for d in reversed(body17)]
    total = sum(d * (3 if i % 2 == 0 else 1) for i, d in enumerate(digits))
    return (10 - (total % 10)) % 10


def validate_sscc(raw: str) -> bool:
    """
    Validates any SSCC string (18 digits or 20 digits with leading (00)).
    """
    clean = "".join(ch for ch in raw if ch.isdigit())
    if len(clean) == 20 and clean.startswith("00"):
        clean = clean[2:]
    if len(clean) != 18:
        return False
    return int(clean[-1]) == calculate_sscc_check_digit(clean[:17])

# Examples:
print(validate_sscc("356012345000000012"))    # True
print(validate_sscc("(00)356012345000000012"))# True
print(validate_sscc("356012345000000019"))    # False (Invalid CD)

Extracting SSCCs from EDIFACT Files

In EDIFACT messages, SSCCs appear in several segments. The most common is GIN with qualifier BJ (Goods Identity Number, SSCC), used in DESADV (Despatch Advice) and IFTMIN (Forwarding Instruction).

Segment Description Example
GIN+BJ:<SSCC> Primary SSCC segment in DESADV / IFTMIN GIN+BJ:356012345000000012'
RFF+SI:<SSCC> Reference, qualifier SI = Shipment ID RFF+SI:356012345000000012'
RFF+AAK:<SSCC> Reference, qualifier AAK = Despatch number RFF+AAK:356012345000000012'
PAC Package segment, SSCC sometimes embedded PAC+1++09:356012345000000012'

Parsing GIN+BJ with JavaScript

/**
 * Extract all SSCCs from an EDIFACT message string.
 * Handles custom UNA delimiters.
 */
function extractSSCCsFromEDIFACT(text) {
    const ssccList = [];

    // Read custom delimiters from UNA service string
    let compSep = ':', elemSep = '+', segTerm = "'";
    const una = text.match(/^UNA(.{6})/);
    if (una) {
        compSep = una[1][0];
        elemSep = una[1][1];
        segTerm = una[1][5];
    }

    const segments = text
        .replace(/
?
/g, '')
        .split(segTerm)
        .map(s => s.trim())
        .filter(Boolean);

    for (const seg of segments) {
        const parts = seg.split(elemSep);
        if (parts[0] !== 'GIN') continue;

        for (const el of parts.slice(1)) {
            const [qualifier, value] = el.split(compSep);
            if (qualifier === 'BJ' && value) {
                const result = validateSSCC(value);
                ssccList.push({ sscc: value, ...result });
            }
        }
    }
    return ssccList;
}
Note on custom delimiters: EDIFACT allows trading partners to define custom component, element and segment separators in the UNA service string. Always read the UNA header before parsing, defaulting to : + ' will silently fail on non-standard files.

SSCC in SAP IDocs (E1EDL44 / EXIDV)

In SAP ERP, ECC, and S/4HANA environments (modules SD, LE, WM, and EWM), SSCC numbers are handled as External Handling Unit Identifiers (HU). They are exchanged in Outbound Delivery, Despatch Advice, and Shipment IDocs like DELVRY03, DELVRY07, and DESADV01.

Segment Field Description
E1EDL37 EXIDV Handling Unit Header: External Handling Unit Identification (18-digit SSCC)
E1EDL44 EXIDV Handling Unit Item: SSCC associated with packed delivery items
E1EDL37 VHILM_KU Customer Packaging Material / Pallet Type code (e.g. EURO PALLET)

Sample XML IDoc segment structure representing a logistics handling unit with SSCC:

<E1EDL37 SEGMENT="1">
    <EXIDV>356012345000000012</EXIDV>
    <VHILM_KU>CHEP-01</VHILM_KU>
    <E1EDL44 SEGMENT="1">
        <VELIN>1</VELIN>
        <EXIDV>356012345000000012</EXIDV>
    </E1EDL44>
</E1EDL37>

Both SSCC Pro Vision and its REST API natively parse these XML IDoc tags as well as flat text IDoc streams up to 1 MB without requiring intermediate transformations.

Frequently Asked Questions

Why does my scanner read a 20 digit SSCC?

Most GS1 128 barcode scanners are configured to read the Application Identifier 00 along with the code itself. An SSCC is strictly 18 digits long. You must always strip the first two zeros before processing the data or validating the check digit.

Can the GS1 Company Prefix length vary?

Yes. Depending on the capacity assigned to the company by the local GS1 member organization, the company prefix can range from 7 to 10 digits. The Serial Reference length adjusts automatically so that the total code length remains exactly 18 digits.

Is the SSCC check digit algorithm the same as the GTIN?

Yes. Both use the standard GS1 Modulo 10 algorithm. However, because the total length is different (18 digits for SSCC vs 13 or 14 for GTIN), the alternating multipliers of 3 and 1 will align differently starting from the rightmost digit.

What is the difference between an SSCC and a GTIN?

A GTIN (Global Trade Item Number) identifies a specific class of trade item like a specific model of a laptop. An SSCC identifies a unique physical logistics unit like a specific pallet containing fifty of those laptops. Every SSCC is globally unique to that exact physical shipment.

Can I reuse an SSCC number?

According to GS1 General Specifications, an SSCC must not be reallocated within one year of the shipment date. However, to ensure pristine global traceability and avoid conflicts in modern tracking systems, many companies choose to never reuse their serial references.

Where is the SSCC located in SAP IDocs?

In SAP Outbound Deliveries (such as IDoc types DELVRY03, DELVRY07, or DESADV01), the 18-digit SSCC is stored under the Handling Unit Item segment E1EDL44 in field EXIDV (External Handling Unit Identification), as well as in the Handling Unit Header segment E1EDL37.

How to calculate the GS1 SSCC check digit in Python?

Reverse the 17-digit payload string, multiply digits at odd indices (0-indexed even) by 3 and even indices by 1, sum the products, and calculate (10 - (sum % 10)) % 10. See our Python Implementation section above for the full function.
